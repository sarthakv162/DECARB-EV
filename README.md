## 1. Executive Summary & Core Principle

Electric delivery depots have significant overnight dwell time. Unmanaged charging upon arrival causes severe power spikes that exceed transformer capacities, charges during dirty grid hours, and incurs peak tariffs.

> **"We don't optimize for the greenest schedule. We optimize for the greenest schedule that the depot can actually operate."**

- **Not primarily an EV charging app:** It is a constrained scheduling, disruption handling, and agentic re-planning system.
- **Safety Boundary:** LLMs are **never** used for safety-critical math. The schedule is mathematically generated by **Google OR-Tools CP-SAT** and certified by an independent **Deterministic Safety Validator**. The AI agent (**Amazon Bedrock / Strands**) orchestrates tools, translates disruptions, explains operational decisions in plain English, and gates execution behind a Human-in-the-Loop (HITL) approval card.

## 3. Disruption Scenarios Demonstrated

1. **⚡ Inverter Failure (Charger C04 Trips Offline at 21:15):**
   - 4 vehicles assigned to C04 are orphaned.
   - The Bedrock agent detects the failure, calls the CP-SAT optimizer to re-route charging across remaining 9 operational chargers during clean 01:30–04:30 night windows.
   - Validator proves 0 violations and 100% departure readiness.
   - Operator inspects delta (cost $+₹140$, 0 missed departures) and clicks **Approve & Dispatch**.
2. **⏱️ Route Delay & Low SOC Deviation (Van V08 Arrives Late at 20:30 with 12% SOC):**
   - Dwell window compressed; agent elevates V08 priority and shifts lower-urgency vans.
3. **🌱 Grid Carbon Spike Alert (Renewable Curtailment at 01:00):**
   - Grid emissions factor spikes by +0.32 kg/kWh; system shifts flexible load to preserve carbon savings.
4. **🔧 Hardware Restored (Charger C04 Repaired):**
   - Rebalances load evenly across all 10 bays.

## 5. Quickstart & Local Run

### Prerequisites
- Python 3.10+ (tested on Python 3.14)
- Modern web browser

### Setup & Run
```bash
# 1. Clone repository
cd AWS_HACK

# 2. Activate virtual environment
source .venv/bin/activate

# 3. Start the FastAPI server
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

### Access Console
Open your browser to:
👉 **`http://127.0.0.1:8000`**

- View the **Site Load & Carbon Envelope** canvas chart.
- Toggle to the **40-Vehicle Gantt Schedule** matrix.
- Click **Inverter Fault: Trip C04** to see the Bedrock Agent produce the re-plan and explanation.
- Click **Approve & Dispatch Plan** to execute the human-in-the-loop sign-off.

## 6. Deploying to Live AWS (AWS CDK)

You can provision all real AWS services directly into your AWS account with a single command:

### 1. Configure AWS Credentials
Edit `.env` (or run `aws configure`):
```env
AWS_ACCESS_KEY_ID=AKIA...
AWS_SECRET_ACCESS_KEY=wJal...
AWS_DEFAULT_REGION=us-east-1
```

### 2. Deploy Infrastructure
Run the automated deployment script:
```bash
./deploy_aws.sh
```

This provisions via **AWS CDK (Python)**:
- **4x Amazon DynamoDB Tables** (`EVDepotFleetState`, `EVDepotChargerState`, `EVDepotActiveSchedules`, `EVDepotDisruptions`) with On-Demand billing.
- **Amazon EventBridge Bus** (`ev-depot-bus`) for real-time disruption routing.
- **Amazon Bedrock IAM Roles** allowing Claude 3.5 Sonnet live invocation.
- **Amazon CloudWatch Dashboard** (`EVDepot-Operational-Orchestration`) with live widgets for carbon avoided, cost saved, and transformer load.
- **CloudWatch Alarm** (`EVDepot-TransformerOverloadRisk`) triggering alerts if transformer exceeds 250 kW.

### 3. Verify Live Cloud Connection
Restart the backend:
```bash
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```
Open **`http://127.0.0.1:8000`** — the top header will display **`AWS LIVE (us-east-1)`** and all fleet state and disruption approvals will sync to your real AWS DynamoDB and CloudWatch dashboard in real time!
